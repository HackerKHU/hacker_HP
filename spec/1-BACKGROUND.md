# 1. 배경

이 문서는 무엇을 만들고 어디까지가 범위인지, 어떤 기술 위에 서는지, 그리고 아직 결정되지 않은 것이 무엇인지를 잡아준다. 다른 모든 문서는 여기서 정의한 범위와 용어를 전제로 쓴다.

```text
§1-1   목적            왜 만드는가
§1-2   범위            포함과 미포함
§1-3   용어            문서 전체에서 쓰는 말
§1-4   기술 스택       무엇 위에 서는가
§1-5   미결정 사항     착수 전에 정해야 할 것
§1-6   1차 출시 범위   MVP와 이후 범위
```

## 1-1 목적

동아리 구성원이 학습 자료(시험 정리본, 과목 정리본)를 공유하고, 공지사항과 활동 사진을 확인할 수 있는 **폐쇄형 커뮤니티 사이트**를 구축한다.

폐쇄형이라는 것이 이 제품의 성격을 결정한다. 가입은 관리자 승인제이고, 승인되지 않은 사용자는 회원 콘텐츠에 접근할 수 없다. 시험 정보와 과목 정리본은 유출되면 곤란한 자료이므로, 접근 통제가 부가 기능이 아니라 제품의 전제다.

**예외는 공개 랜딩 페이지 하나다.** 동아리를 외부에 소개하고 지원자를 받으려면 로그인 없이 볼 수 있는 얼굴이 필요하다. 랜딩은 인증 영역 밖에 있고 회원 데이터를 담지 않으므로 폐쇄형 원칙과 충돌하지 않는다 ([3-3 결정 8](3-3-DESIGN-DECISIONS.md#3-3-9-결정-8--공개-랜딩-페이지를-1차-출시에-포함하고-정적으로-구현한다)).

## 1-2 범위

| 포함 | 미포함 |
|---|---|
| 공개 랜딩 페이지 (동아리 소개·활동사진·통계·FAQ·후원) | 모바일 앱 / 반응형 모바일 UI |
| 회원 가입 승인제, 로그인/로그아웃 | 댓글, Q&A |
| 자료 업로드·검색·다운로드·즐겨찾기 | 알림(이메일/푸시) |
| 공지 게시 및 상단 고정 | 자료 신고 기능 |
| 활동 사진 다중 업로드 및 리사이즈 | 통계 대시보드, 감사 로그 |
| 관리자 회원 관리 | |

**회원 콘텐츠는 승인된 회원만 접근하고, 그중 공개된 것은 랜딩뿐이다.** 로그인·회원가입 신청 화면은 원래 비로그인용이므로 이 제한의 대상이 아니다 (§3-1-3 매트릭스). 랜딩은 정적으로 구현하며 콘텐츠를 코드에 포함한다 ([3-3 결정 8](3-3-DESIGN-DECISIONS.md#3-3-9-결정-8--공개-랜딩-페이지를-1차-출시에-포함하고-정적으로-구현한다)).

미포함 항목은 **하지 않기로 결정한 것**이다. 필요해지면 범위 확장을 [3-3](3-3-DESIGN-DECISIONS.md)에 결정으로 기록하고 시작한다.

위 표는 제품의 최종 범위다. 구현 순서는 §1-6의 출시 단계가 결정하며, `Post Launch` 항목도 제품 범위에서 제거된 것은 아니다.

## 1-3 용어

| 용어 | 정의 |
|---|---|
| 자료 | 시험 정리본 및 과목 정리본을 통칭 |
| 정리본 | 사용자가 업로드한 학습 문서 (파일 1개 이상) |
| 승인 | 관리자가 가입 신청을 수락하여 `PENDING` → `ACTIVE`로 전환하는 행위 |
| 부원 | `ACTIVE` 상태의 일반 사용자 (`USER` role) |
| 관리자 | `ADMIN` role을 가진 사용자 |

Role과 Status의 정확한 정의는 [3-1](3-1-DESIGN-ARCHITECTURE.md)이 원본이다.

## 1-4 기술 스택

| 영역 | 선택 |
|---|---|
| 저장소 | 모노레포 — `apps/api`, `apps/web`, `infra/terraform` ([3-3 결정 1](3-3-DESIGN-DECISIONS.md)) |
| 백엔드 | Spring Boot 3.5 / Java 21 / Gradle (Kotlin DSL) |
| 프론트엔드 | React 19 + TypeScript + Vite → Vercel |
| DB | PostgreSQL 16 (RDS `db.t4g.micro`) |
| 파일 저장 | S3, presigned URL로 서버를 거치지 않고 직접 업로드·다운로드 |
| 인프라 | ECS Fargate Spot + ALB, NAT Gateway 없음 ([3-3 결정 2·3](3-3-DESIGN-DECISIONS.md)) |
| 시크릿 | SSM Parameter Store SecureString ([3-3 결정 4](3-3-DESIGN-DECISIONS.md)) |
| CI 인증 | GitHub OIDC (액세스 키를 저장하지 않는다) |
| 로그인 | 구글 OAuth 2.0 (`khu.ac.kr` 도메인 제한) ([3-3 결정 13](3-3-DESIGN-DECISIONS.md#3-3-14-결정-13--가입로그인을-구글-oauth로-한다)) |

## 1-5 미결정 사항

**이 표가 비어야 Baseline v2다.** 각 항목은 관련 기능 구현에 착수하기 전에 결정되어야 한다 (MUST).

| # | 항목 | 선택지 / 상태 | 언제까지 |
|---|---|---|---|
| 4 | 삭제된 회원의 업로드 자료 처리 | 유지 권장 (업로더 표시만 "탈퇴한 회원"으로 대체) | 회원 삭제 기능 착수 전 |
| 5 | 활동사진 업로드 경로 | 서버 리사이즈가 필요해 multipart로 서버를 거치는데, Vercel 프록시 본문 제한(4.5MB)에 걸린다. presigned 업로드 후 서버가 S3에서 읽어 리사이즈하는 방식으로 바꿀지 결정 필요 | 사진 기능 착수 전 |

> #1(허용 학교 이메일 도메인), #2(세션 방식), #3(최초 관리자 계정 생성 방법)은 확정되어 아래 "이미 확정된 것"으로 옮겼다.

번호는 처음 매긴 것을 그대로 둔다. 닫힌 항목의 번호를 재사용하면 다른 문서의 참조가 어긋난다.

## 1-6 1차 출시 범위

1차 운영을 위해 기능을 두 단계로 나눈다 ([3-3 결정 7](3-3-DESIGN-DECISIONS.md#3-3-8-결정-7--1차-출시를-인증회원-관리공지로-제한한다)). 세부 명세는 구현 중 관련 PR에서 갱신할 수 있지만, `Post Launch` 기능을 MVP에 다시 넣으려면 일정과 담당자를 먼저 확인한다.

| 단계 | 기능 |
|---|---|
| **MVP** | 공개 랜딩 (정적) — 동아리 소개, 활동사진, 통계, FAQ, 후원 |
| **MVP** | 가입, 로그인, 로그아웃, 승인 대기 |
| **MVP** | 관리자 가입 승인, 회원 상태 관리, 회원 관리 화면 |
| **MVP** | 공지 등록·조회·수정·삭제, 상단 고정 |
| **MVP** | React 프론트엔드, Spring API, PostgreSQL, Vercel·ECS Fargate 배포 |
| **Post Launch** | 자료 CRUD, 검색·필터, 즐겨찾기, S3 업로드·다운로드 |
| **Post Launch** | 활동사진 조회·업로드·리사이즈 |
| **Post Launch** | 가입 거부, 회원 제거, 관리자 권한 부여·회수 |
| **Post Launch** | 랜딩 콘텐츠 관리자 편집 |

랜딩은 **정적으로** 구현한다. 소개 문구·활동사진·통계 숫자·FAQ·후원사 로고를 모두 코드에 포함하고 API를 쓰지 않는다 ([3-3 결정 8](3-3-DESIGN-DECISIONS.md#3-3-9-결정-8--공개-랜딩-페이지를-1차-출시에-포함하고-정적으로-구현한다)). 활동사진 조회 API는 `Post Launch`이므로, 랜딩이 그것을 쓰면 `Post Launch`를 MVP로 끌어오게 된다.

MVP에서 제외된 기능의 기존 요구사항과 API 계약은 삭제하지 않는다. 구현 시점만 연기하며, GitHub Issues의 `Post Launch` 마일스톤에서 관리한다.
