# 3-3. 결정 기록

무엇을 택했고 **무엇을 버렸는지** 남긴다. 트레이드오프 칸이 이 문서의 존재 이유다 — 포기한 것을 적어두면, 나중에 그 포기가 아파올 때 "실수"가 아니라 "조건이 바뀌었으니 다시 결정할 시점"이 된다.

**이미 쓴 결정은 고치지 않는다** (MUST). 뒤집을 때는 새 번호를 추가하고 "N번을 대체함"이라고 적는다.

```text
§3-3-1   결정 1   모노레포로 구성한다
§3-3-2   결정 2   NAT Gateway를 쓰지 않는다
§3-3-3   결정 3   ECS Fargate Spot을 쓴다
§3-3-4   결정 4   시크릿은 SSM Parameter Store로 관리한다
§3-3-5   결정 5   도메인 없이 Vercel 프록시로 HTTPS를 우회한다
§3-3-6   비기능 제약   보안 원칙과 제약값
```

## 3-3-1 결정 1 — 모노레포로 구성한다

**상태** 승인됨 · 2026-08-01

**배경** 백엔드(Spring Boot), 프론트엔드(React), 인프라(Terraform)로 구성된다. 인원이 적고 저장소를 여러 개로 나눠 관리할 여력이 없다.

**결정** `apps/api`, `apps/web`, `infra/terraform`을 GitHub Organization 안의 단일 저장소에 둔다.

**이유** 이슈·PR·문서를 한곳에서 추적할 수 있고, 프론트-백엔드 계약이 바뀔 때 한 PR로 같이 리뷰할 수 있다. 소규모 팀에서 멀티레포는 동기화 비용만 늘린다.

**트레이드오프** CI 워크플로에서 `paths` 필터를 신경 써야 한다. 팀·제품이 커지면 각 앱을 독립 배포 주기로 떼어낼 필요가 생길 수 있다.

## 3-3-2 결정 2 — NAT Gateway를 쓰지 않는다

**상태** 승인됨 · 2026-08-01

**배경** 프라이빗 서브넷에서 인터넷으로 나가려면 보통 NAT Gateway가 필요하다. 그런데 NAT Gateway는 월 5~6만원으로, 프로젝트 전체 예산(월 3.5만원 목표)을 그것만으로 초과한다.

**결정** NAT Gateway를 두지 않는다. ECS 태스크는 퍼블릭 서브넷에 `assign_public_ip = true`로 배치해 ECR·SSM에 접근하고, 인바운드는 보안그룹(ALB SG만 허용)으로 막는다. RDS는 아웃바운드가 필요 없으므로 프라이빗 서브넷에 완전히 격리한다.

**이유** NAT은 "프라이빗 서브넷에서 인터넷 나가는 배관"일 뿐 그 자체로 보안 요소가 아니다. SG를 CIDR이 아니라 **SG 참조**로 제한하면 퍼블릭 서브넷에 있어도 외부에서 태스크에 직접 접근할 수 없다.

**트레이드오프** 태스크의 퍼블릭 IP가 노출된다(SG로 차단되지만 네트워크 경로 자체는 열려 있다). 부원 수·예산이 늘면 라우트 테이블 수정 수준으로 NAT을 다시 추가할 수 있다.

## 3-3-3 결정 3 — ECS Fargate Spot을 쓴다

**상태** 승인됨 · 2026-08-01

**배경** EC2 직접 관리, Fargate 온디맨드, Fargate Spot을 검토했다. 동아리 규모상 서버 관리 인력이 없고, dev 환경은 24/7 무중단이 필수가 아니다.

**결정** ECS Fargate Spot을 기본 용량 공급자로 쓴다(`FARGATE_SPOT`, weight 1). EC2를 직접 운영하지 않는다.

**이유** Fargate는 서버 패치·스케일링을 직접 하지 않아도 된다. Spot은 온디맨드 대비 약 1/3 비용이며, 배포 서킷 브레이커와 ALB 헬스체크를 같이 쓰면 회수 시에도 대부분 무중단으로 넘어간다.

**트레이드오프** AWS가 용량을 회수하면 태스크가 재시작되며 짧은 응답 끊김이 생길 수 있다. 엄격한 무중단이 필요해지면 온디맨드 weight를 섞어야 한다.

## 3-3-4 결정 4 — 시크릿은 SSM Parameter Store로 관리한다

**상태** 승인됨 · 2026-08-01

**배경** DB 비밀번호 등을 어디에 둘지 정해야 했다. 후보는 AWS Secrets Manager와 SSM Parameter Store(SecureString)였다.

**결정** SSM Parameter Store의 `SecureString`으로 관리하고, ECS 태스크 정의의 `secrets` 블록에서 직접 참조한다. Secrets Manager는 쓰지 않는다.

**이유** SecureString은 Standard 티어에서 무료다. Secrets Manager는 시크릿 하나당 월 0.4달러다. 자동 로테이션 같은 전용 기능은 지금 단계에서 불필요하다. 어느 쪽이든 앱 코드에 시크릿이 하드코딩되지 않는다는 목표는 동일하게 달성된다.

**트레이드오프** 자동 로테이션, 크로스 계정 공유를 포기한다. 필요해지면 Terraform 리소스 교체 수준의 마이그레이션이다.

## 3-3-5 결정 5 — 도메인 없이 Vercel 프록시로 HTTPS를 우회한다

**상태** 승인됨 — **임시 조치. 공개 전 재검토 필수** · 2026-08-01

**배경** ALB 기본 DNS(`*.elb.amazonaws.com`)에는 ACM 인증서를 발급할 수 없어 ALB가 HTTP만 제공한다. 프론트엔드는 Vercel(HTTPS)에 있어 브라우저가 mixed content로 HTTP API 호출을 차단한다. 도메인은 아직 구매 전이다.

**결정** `apps/web/vercel.json`의 rewrites로 `/api/*`를 Vercel Edge가 ALB(HTTP)로 프록시한다. 브라우저는 Vercel과만 HTTPS로 통신한다.

**이유** 도메인 구매·ACM 발급 없이 기능 개발과 통합 테스트를 즉시 시작할 수 있다. 부수 효과로 same-origin이 되어 쿠키 설정이 `SameSite=Lax`로 단순해진다.

**트레이드오프** Vercel↔ALB 구간이 평문 HTTP로 공개 인터넷을 지난다. 더구나 **ALB 자체가 `0.0.0.0/0:80`으로 열려 있어, ALB DNS를 아는 누구나 프록시를 건너뛰고 평문으로 API를 직접 호출할 수 있다.**

> **실제 부원 계정·비밀번호·시험 자료를 이 상태로 다루지 않는다** (MUST). 개발·테스트와 더미 데이터에만 쓴다. 공개 전 조건은 [7-DEPLOYMENT](7-DEPLOYMENT.md)에 있다.

## 3-3-6 비기능 제약

### 보안 원칙

- 비밀번호는 bcrypt 등 단방향 해시로 저장한다 (MUST).
- **S3 버킷은 완전 비공개로 두고 퍼블릭 액세스 차단을 켠다** (MUST). 파일 접근은 짧은 유효시간의 presigned URL로만 제공하며, 영구적인 공개 URL을 만들지 않는다.
- 업로드 파일명은 서버에서 UUID로 재생성해 저장하고, 원본 파일명은 DB에만 보관한다 (MUST).
- 모든 관리자 API는 서버 측에서 권한을 재검증한다 (MUST) — [3-1 §3-1-7](3-1-DESIGN-ARCHITECTURE.md).
- 시크릿을 코드나 yml에 하드코딩하지 않는다 (MUST).

### 제약값

| 항목 | 값 |
|---|---|
| 자료 파일 최대 용량 | 20MB / 파일 |
| 자료 최대 첨부 개수 | 10개 |
| 이미지 리사이즈 기준 | 가로 최대 1920px, JPEG 품질 85 |
| 목록 기본 페이지 크기 | 20 |

### 대상 환경

데스크톱 웹 브라우저(Chrome, Edge 최신 버전 기준). 모바일 대응은 범위 밖이다 ([1-BACKGROUND §1-2](1-BACKGROUND.md)).
